# 《雨中冒险 2》全角色构筑攻略站设计

日期：2026-08-25  
仓库：`citizen204/ror2-build-guide-cn`  
发布目标：公开 GitHub Pages

## 1. 目标

制作一个面向《雨中冒险 2》全 DLC 玩家的中文静态攻略站。用户能够在手机或电脑浏览器中按角色查找完整构筑，不需要安装游戏插件，也不会读取游戏进程、存档或个人信息。

攻略覆盖制作时 Steam 当前版本中，本体、《虚空幸存者》（Survivors of the Void）、《风暴探寻者》（Seekers of the Storm）和《合金意念》（Alloyed Collective）可用的全部幸存者，包括隐藏角色。每名角色同时提供单人季风/天蚀取向的稳定构筑，以及朋友联机时的调整建议。

成功标准：

- 每名当前可玩角色都有独立、可分享的详情链接。
- 每份攻略都包含技能、构筑逻辑、物品作用、统率路线、虚空物品、月球物品、主动装备和实战循环。
- 技能和装备同时显示图标、中文名和英文名；用户能按英文名在 Rainshift 中搜索。
- 首页搜索、DLC 筛选和所有角色链接在手机与电脑上均可用。
- GitHub Pages 的角色详情链接可直接打开和刷新，不出现 404。
- 网站和源代码公开，但不展示仓库所有者的邮箱或其他私人资料。

## 2. 产品边界

网站是独立的只读攻略，不实现以下功能：

- 游戏内悬浮层、插件或实时箱子识别。
- 修改游戏、存档或 Rainshift 配置。
- 登录、评论、云同步或后端数据库。
- 自动根据一局游戏中的随机掉落实时推荐。

## 3. 信息架构

### 3.1 首页

首页首屏展示站点名称、版本日期、搜索框和 DLC 筛选。角色卡片包含头像、中文名、英文名、所属 DLC、定位和操作难度。搜索同时匹配中英文名；筛选支持“全部、本体、SOTV、SOTS、AC”。

首页还提供简短使用说明：攻略以稳定通关为主要目标，统率神器可直接按优先级选装；无统率时仍可参考每件物品的作用和替代关系。

### 3.2 角色详情页

角色详情使用固定内容顺序，避免用户在不同角色页面重新学习布局：

1. 角色头像、定位、难度、核心玩法摘要。
2. 推荐技能组与“默认拥有 / 需要解锁或修改”标记。
3. 构筑逻辑和技能循环。
4. 单人构筑。
5. 联机构筑调整。
6. 统率神器的前期、中期、后期选装路线。
7. 虚空物品的推荐、条件推荐和避坑。
8. 月球物品的推荐、条件推荐和禁止拿取。
9. 主动装备与装备替代项。
10. 传送器、Boss、飞行怪和最终关卡的打法速记。

页面底部提供上一个角色、返回首页、下一个角色。桌面端使用固定目录方便跳转，手机端使用紧凑的章节导航和回到顶部按钮。

### 3.3 分享与路由

采用 Hash 路由，例如 `/#/survivors/acrid`。这种链接可直接分享，并能在 GitHub Pages 上刷新而不依赖服务器重写规则。

## 4. 每名角色的内容规范

### 4.1 技能配置

每个技能位展示技能图标、中文名、英文名、选择理由和解锁状态。推荐技能以当前补丁下季风/天蚀的稳定性、伤害、机动性和容错率综合判断；存在玩法分支时，明确给出主推荐与可替换方案，而不把个人偏好描述成唯一答案。

### 4.2 构筑逻辑

先用简短文字解释角色的主要伤害来源、触发频率、攻击范围、生存方式和技能循环，再说明物品为什么能强化这些机制。攻略保持此前厨师、虚空子嗣和呛鼻毒师版本的讲解风格：不仅列物品，还解释每件物品解决什么问题。

### 4.3 物品优先级

单人构筑按白装、绿装、红装、首领装和主动装备分组。每件物品包含：

- 图标、中文名和英文名。
- 优先级和建议数量或停止堆叠点。
- 对当前角色的具体作用。
- 与技能或其他物品的关键联动。
- 不适合时的替代选择。

统率路线按游戏阶段给出可执行顺序，避免只有笼统的物品梯度表。无统率玩法仍可通过优先级和替代项判断随机掉落是否值得拿。

### 4.4 单人与联机

单人方案以季风/天蚀稳定通关为基准。联机部分不重复整套清单，而是明确说明：角色必需品、可以让给队友的装备、团队定位、共享资源冲突和联机时应调整的技能或装备。

### 4.5 虚空与月球物品

虚空物品必须写清会腐化哪件原物品、腐化后的收益、推荐数量，以及是否会破坏原构筑。月球物品按“推荐、条件推荐、避免”分级，并说明其副作用和拿取条件。主动类月球装备与被动月球物品分开显示。

## 5. 数据与组件设计

使用 React、TypeScript 和 Vite 构建纯静态网站。内容与界面分离：

- `survivors` 数据保存角色元数据、技能配置、玩法逻辑和各章节内容。
- `items` 数据保存物品中英文名、稀有度、图标、通用说明和来源。
- 角色攻略通过物品 ID 引用公共物品数据，并补充该角色专属说明，减少重复和名称不一致。
- 页面组件负责首页筛选、角色卡片、技能组、物品组、提示框、章节导航和前后角色切换。

数据加载失败或角色 ID 不存在时显示中文错误页，并提供返回首页按钮。单个图标加载失败时保留物品名称和占位样式，不让整页不可用。

## 6. 视觉与可访问性

整体采用深色科幻风格，参考游戏氛围但不复制游戏菜单。稀有度使用一致颜色：普通、稀有、传奇、首领、月球和虚空各有清晰视觉区分，同时保留文字标签，避免只依赖颜色传递信息。

角色与物品使用真实游戏图标；图片保存为站点本地资源，提供替代文本和来源说明，以避免第三方热链失效。页面正文保持高对比度，按钮和链接具备键盘焦点样式，手机触摸目标不小于常用可用性尺寸。

手机端角色卡改为单列，物品卡片使用图标加紧凑文字；桌面端使用多列布局。动画仅用于轻微过渡，并尊重系统的“减少动态效果”设置。

## 7. 资料来源与版本标记

角色名单、技能名称、物品效果和补丁状态在实施阶段通过当前官方补丁说明、Steam DLC 页面和可靠的《雨中冒险 2》资料站交叉核对。技术性问题优先使用官方资料；官方未提供完整数值时，使用维护活跃的百科资料并在网站“资料与版本”区域列出链接和核对日期。

攻略判断属于基于机制和通关目标形成的编辑建议，会与可验证的游戏数值分开表达。网站页脚显示“最后核对日期”和适用 DLC，避免未来补丁后让旧建议看起来仍是最新结论。

## 8. 测试与验收

发布前执行以下检查：

- TypeScript 编译和生产构建通过。
- 中英文搜索、清空搜索和每个 DLC 筛选正确。
- 完整角色名单均能从首页进入详情页。
- 每个角色攻略通过数据完整性检查，必需章节不得为空。
- 代表性的本体、SOTV、SOTS 和 AC 角色页面内容与图片正确。
- 不存在重复角色 ID、无效物品引用或缺失本地图标。
- 手机窄屏和常见桌面宽度下无横向溢出，导航可操作。
- 键盘可访问搜索、筛选和详情链接。
- GitHub Pages 公开链接、Hash 详情链接和刷新行为正常。

## 9. 发布与维护

项目使用本地 Git 仓库，最终推送到公开仓库 `citizen204/ror2-build-guide-cn`。通过 GitHub Actions 构建并部署到 GitHub Pages。Git 提交身份可在本地使用用户提供的 GitHub 名称和邮箱，但网页内容、元数据和可见文案不得包含该邮箱。

README 说明网站用途、本地开发、数据结构、更新内容的方法和素材来源。角色与物品数据独立保存，使未来游戏补丁只需更新受影响的数据与版本日期。
